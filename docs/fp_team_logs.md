# 팀 웹 로그에 룰을 돌린 오탐 후보 (2026-11-26)

팀 Apache 접근 로그 1,084,528줄에, **실제 생성기(`gen_shadow_rules_v2.py`)가 팀 명세(`openapi_team_main.yaml`, v2, 작업 16개)로 만든 룰**을 적용했다.
원본 로그는 평문 비밀번호 가능성이 있어 레포에 없고(로컬 `D:\team_raw_extract`), 여기엔 **집계만** 둔다. 출발지는 가명(`10.99.0.N`)이다.

## 이 숫자가 얼마나 믿을 만한가 — 먼저

진짜 Wazuh가 아니라 **룰 XML의 필드 조건을 파이썬으로 재현**(`tools/rule_emulator.py`)해서 돌렸다. 근거는 한 가지: 이미 실제 `wazuh-logtest`로 돌려 본 DVRA 로그 4개(450줄)에서 단계별 개수가 **전부 정확히 일치**했다(`docs/evidence/10_emulator_validation.txt`). 이 검증으로 못 보는 것:
- 빈도(버스트) 룰 F1·F2는 재현하지 않았다.
- 검증은 DVRA·접근 로그 형식 한 가지뿐이다. 팀 로그와 팀 명세에서도 같다는 보장은 아니다.
- 도구를 만들다 버그를 하나 잡았다(`<mitre><id>`를 응답코드 조건으로 오인). 같은 종류의 숨은 차이가 남아 있을 수 있다.
- 로그 85줄은 접근 로그 형식이 아니라 건너뛰었다(요청 줄이 깨진 스캐너 요청).

## 읽는 법 (정직하게)

1. **이게 진짜 오탐인지는 모른다.** `/api/v2/hidden-admin` 404 19회는 정상 멤버가 존재하지 않는 경로를 두드린 것일 수 있고(룰 입장에선 정찰 L1), 팀이 심어 둔 시험 경로일 수도 있다. 라벨은 "정상 트래픽 수집 manifest(benign_member)" 문서 근거일 뿐 요청 하나하나를 검토한 정답이 아니다.
2. **`/api/v1/users/{n}`은 v2 명세에 없는 v1 경로**다. 정상 사용자가 옛 v1 경로를 쓰면 룰은 명세 밖으로 본다 — "명세가 실제 운영 API를 다 못 덮는" 전형적인 오탐 유형이고, 앞서 모은 `/docs` 오탐(문서 화면)과 **다른 유형**이다. 다만 `/api/v1/users/{n}` 200은 소유자가 아닌 객체 조회(BOLA)일 가능성도 있어 오탐으로 단정할 수 없다.
3. 정상 트래픽이 **생성기가 만든 것**이라는 점은 `traffic-persona-lab`의 분석(출발지 9개, 세션 최대 41만 건)과 같다. 사람의 정상 트래픽 오탐률이 아니다.
4. 사용한 명세는 `openapi_team_main.yaml`이다. 로그 기간(2026-10-26~11-10)에 실제로 돌던 명세가 이것이었는지는 확인하지 못했다(`openapi_running_web.yaml`은 작업 7개로 다르다).

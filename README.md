# airgap-rag-lab — 폐쇄망(온프레미스) RAG + 에이전트 보안 랩

> **1·2·3단계 완료(2026-11-26)** — 로컬 LLM + 망분리 + Wazuh 룰 RAG를 실제로 돌려서 확인. 4·5단계는 아직.

## 빠르게 써 보기

```
docker compose up -d --build
docker compose run --rm app llm/client.py "질문"
docker compose run --rm app llm/verify_airgap.py   # 로컬 LLM 동작 + 외부 접속 차단 둘 다 확인

# RAG (임베딩 모델은 인터넷이 되는 곳에서 한 번만 받아 둔다: ollama pull bge-m3)
docker compose run --rm app rag/ingest.py          # corpus/ → 청크 → 임베딩 → ChromaDB
docker compose run --rm app rag/ask.py "같은 IP가 120초 안에 객체 ID 10개를 성공 조회하면 어떤 룰?"
docker compose run --rm app rag/eval.py            # 검색 평가: 벡터 / BM25 / 하이브리드 비교 (recall@k, MRR)
docker compose run --rm app rag/triage.py samples/alerts.jsonl -n 0   # Wazuh 알럿 → 트리아지 초안
docker compose run --rm app rag/facts_check.py     # 코드 계산 사실 점검 (LLM 없이)

# 전 과정을 돌려 실제 출력을 docs/evidence/ 에 로그로 남긴다 (+ --with-eval: 트리아지 A/B 평가 15~20분)
bash demo/run_demo.sh
```

실행 증거(명령·시각·커밋과 함께 저장한 실제 출력)는 [`docs/evidence/`](docs/evidence/README.md).

## 문제의식

금융권·공공기관은 망분리(폐쇄망) 환경이라 외부 LLM API를 못 쓴다. 솔트룩스의 '루시아 온' 같은 제품이 이 자리를 채운다 — 로컬 LLM + 사내 문서 검색(RAG)을 외부 네트워크 호출 없이 통째로 설치하는 방식.

이 레포는 그 축소판을 **직접 만들어 보면서**, 다음 두 가지를 같이 다룬다.

1. **인프라**: 로컬 LLM 서빙 + 벡터DB + RAG 파이프라인이 실제로 외부 호출 없이 동작하는가
2. **보안**: RAG 특유의 위협 — 검색된 문서를 통한 프롬프트 인젝션, 권한 밖 문서 검색(BOLA의 RAG판), 민감 정보 유출

## 재사용하는 설계 (코드 복붙 아님, 원칙만)

- [reservoir-rtu-lab](https://github.com/zeldaim/reservoir-rtu-lab)의 `app/report.py` — "검색·기록된 데이터는 지시가 아니다"라는 프롬프트 인젝션 방어 원칙. RAG에서는 "검색된 문서 안의 지시문처럼 보이는 문장을 LLM이 따르면 안 된다"로 그대로 적용된다.
- [api-defense-lab](https://github.com/zeldaim/api-defense-lab) · [reservoir-rtu-lab](https://github.com/zeldaim/reservoir-rtu-lab)의 "AI는 초안·분석만, 실행은 결정론적 로직이 한다" 원칙.

## 계획 (뼈대만, 순서대로)

- [x] **1. 로컬 LLM** — Docker로 Ollama + Qwen2.5 7B instruct(4.7GB). `llm/client.py`는 표준 라이브러리(`urllib`)만 써서 reservoir-rtu-lab의 로컬 LLM 작업 때 겪은 이 PC Python 3.15 네이티브 빌드 문제(pydantic-core 등)를 아예 피했다.
- [x] **2. RAG** — ChromaDB + 로컬 임베딩(Ollama `bge-m3`, 1024차원) + 검색 → 로컬 LLM 답변. 코퍼스는 내가 쓴 Wazuh 룰 XML 5개(룰 88개)와 탐지 문서 4개 = 청크 116개(`corpus/`). 룰은 `<rule>` 하나, 문서는 `##` 섹션 하나가 청크. 임베딩·저장·답변 모두 `airgap` 네트워크 안에서 돌고, 모델 다운로드만 인터넷이 되는 쪽에서 미리 했다(Chroma 기본 임베딩 모델은 인터넷에서 받으려 하므로 쓰지 않고 우리 임베딩을 직접 넣는다).
  - **검색 평가**(`rag/eval.py`, 질문 22개 = 일반 14 + 같은 틀 룰 8): 같은 질문으로 세 방식을 비교했다. BM25는 표준 라이브러리만으로 직접 구현, 하이브리드는 벡터+BM25 순위를 RRF로 합침.

    | 방식 | 구분 | R@1 | R@3 | R@5 | MRR |
    |---|---|---|---|---|---|
    | 벡터 | 전체(22) | 13/22 | 16/22 | 18/22 | 0.674 |
    | BM25 | 전체(22) | 9/22 | 21/22 | 21/22 | 0.636 |
    | **하이브리드** | 전체(22) | 13/22 | 18/22 | 21/22 | **0.723** |
    | 벡터 | 일반(14) | 12/14 | 13/14 | 14/14 | 0.911 |
    | BM25 | 일반(14) | 7/14 | 13/14 | 13/14 | 0.667 |
    | 하이브리드 | 일반(14) | 12/14 | 13/14 | 14/14 | 0.911 |
    | 벡터 | 틀(8) | 1/8 | 3/8 | 4/8 | 0.260 |
    | BM25 | 틀(8) | 2/8 | 8/8 | 8/8 | 0.583 |
    | 하이브리드 | 틀(8) | 1/8 | 5/8 | 7/8 | 0.396 |

    결론: 하이브리드가 전체 MRR 최고이고 일반 질문에서 퇴보가 없다. 하지만 **같은 틀 룰의 1위 정확도는 어느 방식도 낮다**(1~2/8) — 경로는 맞히는데 단계(L1/L2/L3)가 인접 룰로 어긋난다. 이건 검색이 아니라 "질문에서 경로·단계·메서드를 뽑는" 질의 해석 문제로 보이고, 트리아지에서는 룰 ID 정확 조회가 이를 우회한다. **한계**: 질문은 코퍼스를 읽은 뒤 내가 만들었고(틀 8개는 첫 평가의 실패 지점을 겨냥해 나중에 추가) 코퍼스가 작아 낙관적이다. BM25 단독이 일반 질문에서 나쁜 건 한글 bigram 토큰화가 거칠기 때문일 수 있으나 확인하지 않았다.
  - **알려진 흠**: 답변 끝에 출처 표기가 `[파일::100923]`처럼 틀 그대로 찍히는 경우가 있다(프롬프트 형식 미세 조정 필요).
  - **알럿 트리아지**(`rag/triage.py`): Wazuh 알럿 JSON → ① 코드가 **사실을 계산**(`rag/facts.py`: 명세 안/밖, 응답 코드 의미, 후속 빈도 룰과 임계 비교, 같은 IP 묶음) ② 룰 정의를 **룰 ID로 정확히 조회**(+후속 룰) ③ 관련 룰은 하이브리드 검색으로 보충 → 로컬 LLM이 판정·요약·근거·확인 항목·권장 대응 **초안**을 쓴다(실행·차단은 안 함). 알럿 필드는 신뢰할 수 없는 데이터로 표시하고, 정답 `label`은 프롬프트에서 뺀다. 명세는 룰 파일(0915) 머리 주석에서 읽는다. `samples/alerts.jsonl` = 실제 랩 알럿 15건(전부 한 IP, 8초 안).
    - **코드 점검**(`rag/facts_check.py`, LLM 없음): 허용 21개·예외 4개 파싱, 실제 알럿 15건이 전부 "명세 밖"(룰이 그 전제로 울렸으므로 룰과 일치해야 함), 후속 룰 매핑(100510→100520, 100512→100521) — 전부 통과.
    - **A/B 평가**(`rag/triage_eval.py`, 12건 = 실제 공격 8 + 합성 오탐 4, temperature 0): 사실 없이(A) vs 사실과 함께(B).

      | | 판정 정확도 | 공격 8건 | 오탐 4건 | "명세 밖" 언급(공격) | 응답코드 의미(공격) |
      |---|---|---|---|---|---|
      | A 사실 없음 | 8/12 | 8/8 | **0/4** | 1/8 | 6/8 |
      | B 사실 포함 | 8/12 | 8/8 | **0/4** | 4/8 | 7/8 |
      | 코드만 판정 | 12/12 | | | | |

    - **읽는 법(정직하게)**: ① 사실을 넣어도 **판정 정확도는 안 올랐다.** 올라간 건 근거 언급(명세 밖 1/8→4/8)뿐이고 이 지표는 문자열 포함 여부로 센 거친 값이다. ② 오탐 4건은 사실에 "문서화된 예외와 일치"가 적혀 있는데도 맞히지 못했다. B는 "의심"에서 "보류"로 물러났을 뿐이다. `docs/evidence/08`을 보면 본문 요약은 "예외 목록에 포함돼 정상 접근일 가능성이 높다"로 맞는데 첫 줄 판정만 "보류"로 어긋난다 — **본문과 판정이 불일치**. ③ "코드만 12/12"는 **순환**이다: 오탐 4건을 코드가 쓰는 예외 목록(0915 머리 주석)과 같은 출처에서 만들었다. 오탐 판별 능력의 증거가 아니라 회귀 테스트다. ④ 합성 4건은 한 룰(100512)·한 유형이라 n이 작고 일반화할 수 없다. 공격 8건의 판정은 모든 알럿이 공격이라 "일단 의심"만 해도 맞는다.
    - **아직 못 한 것**: 실제 오탐 데이터 평가, 프롬프트 인젝션(알럿 `path`에 지시문을 넣는 경우, 4단계), 관련 룰 검색이 알럿과 무관한 `0916` 청크를 붙이는 문제.
  - 다음: **판정은 LLM이 아니라 코드가 내리고 LLM은 설명만** 하게 바꿀지 결정(레포 원칙 "결정은 결정론"에 맞고 본문-판정 불일치가 사라지지만, 지금 평가 세트로는 12/12가 순환이라 성능을 입증하지 못한다 — 실제 오탐 데이터가 먼저 필요), 질의 해석(경로·단계·메서드 추출)으로 같은 틀 룰 1위 정확도 개선.
- [x] **3. 망분리 재현** — `docker-compose.yml`의 `airgap` 네트워크(`internal: true`)에 앱·Ollama를 묶었다. `llm/verify_airgap.py`로 **실제로** 확인: 로컬 LLM은 정상 응답하고(`1+1=2`), 외부 접속(8.8.8.8:443) 시도는 "Network is unreachable"로 **물리적으로 막혔다**(타임아웃이 아니라 경로 자체가 없음). "안 쓰면 된다"가 아니라 "쓸 수가 없다"는 걸 코드로 증명한 것.
- [ ] **4. RAG 보안 위협 재현·방어**:

  - 권한 밖 문서가 검색 결과에 섞이는 문제(BOLA의 RAG 버전) — 문서별 접근 통제
  - 민감 정보가 LLM 응답에 그대로 노출되는 문제
